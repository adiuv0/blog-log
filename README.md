# Blog Log

A local-first Expo app for reading a blog's archive systematically, oldest to newest or the other way round. Import a blog by its RSS/Atom feed, track what you've read, and open each post on the author's own site.

Everything is stored on the device in SQLite. There is no backend.

## Stack

- Expo SDK 54, React Native 0.81, React 19.1, TypeScript
- Expo Router for navigation (`app/`)
- expo-sqlite with Drizzle ORM (`db/`), FTS5 for search
- TanStack Query for data access (`hooks/`)
- Importers for live feeds plus Wayback Machine snapshots, History4Feed, and JSON files (`services/import/`)
- On-device TextRank summaries (`services/nlp/`)

## Getting started

```sh
npm ci
npm start            # Expo dev server
npm run android      # native Android build (needs the Android SDK)
```

Preview APKs can also be built with EAS: `eas build --profile preview --platform android`.

### Build notes

- **New Architecture is off** (`newArchEnabled: false` in `app.json`) because of NDK linker failures on the Windows build machine. Libraries that require the New Architecture (for example FlashList v2) will crash; the app uses `FlatList` instead.
- The `android/` folder is generated by `expo prebuild` and is git-ignored.

## Checks

```sh
npm test             # unit tests (Vitest)
npm run typecheck    # tsc --noEmit
```

Tests run under Node and cover the pure helpers (date parsing, feed matching, search query building) and the SQL migrations, using Node's built-in SQLite (Node 22.5 or newer).

## Database changes

The base tables are created in `db/ddl.ts`. Any change to an existing table, or any data fix, goes in `db/migrations.ts` as a new numbered migration; the app tracks which ones have run with SQLite's `user_version` pragma. Never edit a migration that has already shipped.
